# RV1126B Linux build

RV1126B uses RKNN2, unlike RV1126/RV1109 (RKNN1). The default build targets
Linux ARMv7 hard-float, matching the tested board, and requires RKNN Runtime **2.3.2 or newer**. The bundled
2.2.0 runtime is not suitable; an external runtime directory is required.
CMake extracts the embedded runtime version and rejects versions older than 2.3.2.

## Environment

Obtain the RKNN-Toolkit2 2.3.2 image from the
[official SDK](https://github.com/airockchip/rknn-toolkit2#download), or build
it using Rockchip's Dockerfile. Tag it `rknn-toolkit2:2.3.2-cp38` (or pass
`--build-arg RKNN_IMAGE=<your-image>` below).

From the InspireFace repository root:

```sh
docker build -f docker/Dockerfile.rv1126b -t inspireface-rv1126b .
git clone --recurse-submodules https://github.com/tunmx/inspireface-3rdparty.git 3rdparty
git clone --depth 1 --filter=blob:none --sparse https://github.com/airockchip/rknn-toolkit2.git 3rdparty/rknn-toolkit2
git -C 3rdparty/rknn-toolkit2 fetch --depth 1 origin 59a913d172e7f5ff03c9076e2ec7b1b1288ffd08
git -C 3rdparty/rknn-toolkit2 checkout 59a913d172e7f5ff03c9076e2ec7b1b1288ffd08
git -C 3rdparty/rknn-toolkit2 sparse-checkout set rknpu2/runtime/Linux/librknn_api
docker run --rm -it -v "$PWD:/workspace" inspireface-rv1126b
```

Skip clones for repositories already present. The tested official runtime
revision is `59a913d172e7f5ff03c9076e2ec7b1b1288ffd08` (2.3.2).
The image adds Ubuntu's ARMv7 hard-float and aarch64 GNU compilers; it is not a board BSP or
firmware SDK. For deployment, use a toolchain/sysroot compatible with the
board's libc and kernel drivers.
The locally checked GCC 9 build references symbols up to `GLIBC_2.29` and
`GLIBCXX_3.4.26` in `libInspireFace.so`; do not assume this binary works on
an older root filesystem. The accompanying runtime has its own ABI requirements.

## Build and checks (inside the container)

```sh
export RKNN_RUNTIME_DIR=/workspace/3rdparty/rknn-toolkit2/rknpu2/runtime/Linux/librknn_api
python3 command/tests/test_rv1126b_build.py
python3 command/tests/rv1126b_conversion_smoke.py
bash command/build_cross_rv1126b_armhf.sh
ctest --test-dir build/inspireface-linux-armhf-rv1126b --output-on-failure
```

The installed SDK is under `build/inspireface-linux-armhf-rv1126b/install/`;
it includes `libInspireFace.so`, the selected `librknnrt.so`, and headers.
The script preserves intermediate build files. Override `BUILD_DIR` or
`JOBS` as needed. `GCC_COMPILER` accepts a compiler prefix (without `-gcc`),
or set `ARM_CROSS_COMPILE_TOOLCHAIN` to a toolchain directory with `bin/`.

RGA is compiled in when the build enables it, but the public image processing
default stays CPU so enabling the RGA source flag does not silently switch
consumers to a hardware path that was not verified on the board. Use
`ISF_ENABLE_RGA=ON` and `HPSET_ImageProcessBackend(RGA)` only for explicit
opt-in after reading the RGA verification section below.

## Validation limits

- Configuration tests check RKNN2 selection, external header/library paths,
  Linux-only validation, and unchanged RK356X/RK3588 runtime selection.
- The conversion smoke test builds a tiny synthetic convolution model.
  It does **not** validate InspireFace's face models or recognition accuracy.
- Cross-compilation and ELF checks do not validate NPU execution. Before
  claiming full device support, convert the actual face models for RV1126B,
  assemble a compatible resource pack, and test detection, landmarks,
  recognition, RGA/DMA paths, and repeated session lifecycle on a board.
- Match the runtime to the board's RKNPU driver. An x86 Docker container
  does not emulate the RV1126B NPU.

## Landmark model board test

The scripts under `command/rv1126b_landmark/` convert a 112x112 BGR ONNX
landmark model, run the same tensor on the board, and compare 106 points.
The source directory must contain `models/_01_hyplmkv2_0.25_112x.onnx`,
`crop.png`, `quant_v2_dataset.txt`, and its referenced images.

```sh
python3 command/rv1126b_landmark/prepare_model.py SOURCE_DIR build/rv1126b-landmark-artifacts
export RKNN_RUNTIME_DIR=/workspace/3rdparty/rknn-toolkit2/rknpu2/runtime/Linux/librknn_api
bash command/rv1126b_landmark/build_runner.sh build/rv1126b-landmark-artifacts/rknn_landmark_runner
```

On Windows, run the board test and compare its output:

```powershell
command/rv1126b_landmark/run_board_test.ps1 -Serial <adb-serial>
python command/rv1126b_landmark/compare_outputs.py `
  build/rv1126b-landmark-artifacts/onnx_output_f32.bin `
  build/rv1126b-landmark-artifacts/rknn_output_f32.bin `
  --input-size 112 --image build/rv1126b-landmark-artifacts/input.png `
  --overlay build/rv1126b-landmark-artifacts/landmark_comparison.png `
  --json build/rv1126b-landmark-artifacts/metrics.json
```

Green points in the overlay are ONNX; red points are board RKNN output.

## Tracking-mode board E2E

The scripts under `command/rv1126b_tracking_e2e/` verify the video tracking
path on the board. They cover LIGHT_TRACK and TRACK_BY_DETECTION single-face
continuity (30 frames, stable track id, nondecreasing track count), LIGHT_TRACK
and ALWAYS_DETECT multi-face (2+ faces, unique ids in tracking mode), a no-face
image, and dense landmark extraction from a tracking-mode token.

On the tested board with the Gundam_RV1126B pack, all six scenarios pass.
Representative single-face LIGHT_TRACK latency is about 6 ms per cached frame
and about 26 ms per re-detect frame (detect interval 5). TRACK_BY_DETECTION
runs full detection every frame at about 26 ms. Multi-face at 640 is about
77 ms per frame on a 2-person scene.

Note: the multi-face test image (`test_res/data/bulk/pedestrian.png`) yields
2 detections at 640 on the RV1126B pack, while the same image yields more on
desktop packs. This is a quantized-model recall difference, not a build issue.

Build and run:

```sh
export RKNN_RUNTIME_DIR=/rknn
export SDK_INSTALL_DIR=/workspace/build/inspireface-linux-armhf-rv1126b/install/InspireFace
bash command/rv1126b_tracking_e2e/build_tracking_runner.sh build/rv1126b-tracking-e2e
```

```powershell
command/rv1126b_tracking_e2e/run_board_tracking_e2e.ps1 `
  -PackPath build/rv1126b-pack/Gundam_RV1126B `
  -Task3Report build/rv1126b-runtime-parity/board/runtime-parity.json
```

## RGA hardware verification

## Stability and concurrent sessions

The scripts under `command/rv1126b_stability_e2e/` run 50 session
create/detect/destroy cycles on the board and verify FeatureHub self-similarity.
On the tested board all 50 cycles pass with 204 KB cumulative RSS growth and
self-similarity 1.0, confirming no crash or meaningful leak under repeated
session churn.

The scripts under `command/rv1126b_concurrent_e2e/` create four independent
sessions and run detection in four threads simultaneously (20 frames each).
All four threads detect the face in every frame; per-frame latency is about
42 ms per thread when the NPU is shared, compared to about 12 ms for a single
session, consistent with expected throughput partitioning.

Both runners follow the same cross-build and deploy pattern as the tracking
runner. Build with `SDK_INSTALL_DIR` pointing to the installed SDK and run the
corresponding `run_board_*.ps1` script with the pack path.

## Face capture state machine

The scripts under `command/rv1126b_capture_e2e/` verify the stateful
`HFFaceCaptureSession` API. On the tested board, feeding a face image for 30
frames with relaxed filters reaches `HF_CAPTURE_STATE_READY` and collects one
capture result at about 0.9 ms per update. A no-face image correctly stays
in `HF_CAPTURE_STATE_IDLE`. Build and deploy with the same pattern.

The bundled 1.10.1 RGA library was not compatible with the RV1126B RGA driver
(`4.1.34669`). On the tested board (kernel 6.1.141), the default heap path
`/dev/dma_heap/system-uncached-dma32` also does not exist; use
`/dev/dma_heap/system-uncached`.

An `armhf` build of `librga 1.10.6_[3]` has now been verified with the GCC 9
cross toolchain. The library is linked statically into `libInspireFace.so`, so
the board does not need `librga.so` at runtime. With
`HFSwitchImageProcessingBackend(HF_IMAGE_PROCESSING_RGA)` selected after
launch, the pipeline matrix completed 5/5 scenarios successfully on the board:
liveness, mask, quality, attribute, and emotion. Each measured case detected one
face and ran at roughly 33 ms per frame.

CPU image processing remains the safe default. The stability and concurrent
runners also accept `--image-backend cpu|rga` (CPU by default) and record the
selected backend in their result evidence. With the verified 1.10.6 build, RGA
completed 50/50 session lifecycle cycles with 28 KB RSS growth and
self-similarity 1.0, and four concurrent sessions each completed 20 frames.
Switch to RGA only after confirming that the target board has the compatible
RGA driver and DMA heap paths, and re-run the pipeline matrix before enabling
it for new consumers.
