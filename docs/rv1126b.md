# RV1126B Linux build

RV1126B uses RKNN2, unlike RV1126/RV1109 (RKNN1). The default build targets
Linux ARMv7 hard-float, matching the tested board, and requires RKNN Runtime **2.3.2 or newer**. The bundled
2.2.0 runtime is not suitable; an external runtime directory is required.
CMake extracts the embedded runtime version and rejects versions older than 2.3.2.

## Environment

Obtain the RKNN-Toolkit2 2.3.2 image from the
[official SDK](https://github.com/airockchip/rknn-toolkit2#download), or build
it using Rockchip's Dockerfile. Tag it `rknn-toolkit2:2.3.2-cp38` (or pass
`--build-arg RKNN_IMAGE=<your-image>` below).

From the InspireFace repository root:

```sh
docker build -f docker/Dockerfile.rv1126b -t inspireface-rv1126b .
git clone --recurse-submodules https://github.com/tunmx/inspireface-3rdparty.git 3rdparty
git clone --depth 1 --filter=blob:none --sparse https://github.com/airockchip/rknn-toolkit2.git 3rdparty/rknn-toolkit2
git -C 3rdparty/rknn-toolkit2 fetch --depth 1 origin 59a913d172e7f5ff03c9076e2ec7b1b1288ffd08
git -C 3rdparty/rknn-toolkit2 checkout 59a913d172e7f5ff03c9076e2ec7b1b1288ffd08
git -C 3rdparty/rknn-toolkit2 sparse-checkout set rknpu2/runtime/Linux/librknn_api
docker run --rm -it -v "$PWD:/workspace" inspireface-rv1126b
```

Skip clones for repositories already present. The tested official runtime
revision is `59a913d172e7f5ff03c9076e2ec7b1b1288ffd08` (2.3.2).
The image adds Ubuntu's ARMv7 hard-float and aarch64 GNU compilers; it is not a board BSP or
firmware SDK. For deployment, use a toolchain/sysroot compatible with the
board's libc and kernel drivers.
The locally checked GCC 9 build references symbols up to `GLIBC_2.29` and
`GLIBCXX_3.4.26` in `libInspireFace.so`; do not assume this binary works on
an older root filesystem. The accompanying runtime has its own ABI requirements.

## Build and checks (inside the container)

```sh
export RKNN_RUNTIME_DIR=/workspace/3rdparty/rknn-toolkit2/rknpu2/runtime/Linux/librknn_api
python3 command/tests/test_rv1126b_build.py
python3 command/tests/rv1126b_conversion_smoke.py
bash command/build_cross_rv1126b_armhf.sh
ctest --test-dir build/inspireface-linux-armhf-rv1126b --output-on-failure
```

The installed SDK is under `build/inspireface-linux-armhf-rv1126b/install/`;
it includes `libInspireFace.so`, the selected `librknnrt.so`, and headers.
The script preserves intermediate build files. Override `BUILD_DIR` or
`JOBS` as needed. `GCC_COMPILER` accepts a compiler prefix (without `-gcc`),
or set `ARM_CROSS_COMPILE_TOOLCHAIN` to a toolchain directory with `bin/`.

RGA is enabled by default, following the other RKNN2 builds. Set
`ISF_ENABLE_RGA=OFF` for CPU preprocessing. This build uses the existing
bundled RGA library; its compatibility with the board's RGA driver still
requires hardware validation.

## Validation limits

- Configuration tests check RKNN2 selection, external header/library paths,
  Linux-only validation, and unchanged RK356X/RK3588 runtime selection.
- The conversion smoke test builds a tiny synthetic convolution model.
  It does **not** validate InspireFace's face models or recognition accuracy.
- Cross-compilation and ELF checks do not validate NPU execution. Before
  claiming full device support, convert the actual face models for RV1126B,
  assemble a compatible resource pack, and test detection, landmarks,
  recognition, RGA/DMA paths, and repeated session lifecycle on a board.
- Match the runtime to the board's RKNPU driver. An x86 Docker container
  does not emulate the RV1126B NPU.

## Landmark model board test

The scripts under `command/rv1126b_landmark/` convert a 112x112 BGR ONNX
landmark model, run the same tensor on the board, and compare 106 points.
The source directory must contain `models/_01_hyplmkv2_0.25_112x.onnx`,
`crop.png`, `quant_v2_dataset.txt`, and its referenced images.

```sh
python3 command/rv1126b_landmark/prepare_model.py SOURCE_DIR build/rv1126b-landmark-artifacts
export RKNN_RUNTIME_DIR=/workspace/3rdparty/rknn-toolkit2/rknpu2/runtime/Linux/librknn_api
bash command/rv1126b_landmark/build_runner.sh build/rv1126b-landmark-artifacts/rknn_landmark_runner
```

On Windows, run the board test and compare its output:

```powershell
command/rv1126b_landmark/run_board_test.ps1 -Serial <adb-serial>
python command/rv1126b_landmark/compare_outputs.py `
  build/rv1126b-landmark-artifacts/onnx_output_f32.bin `
  build/rv1126b-landmark-artifacts/rknn_output_f32.bin `
  --input-size 112 --image build/rv1126b-landmark-artifacts/input.png `
  --overlay build/rv1126b-landmark-artifacts/landmark_comparison.png `
  --json build/rv1126b-landmark-artifacts/metrics.json
```

Green points in the overlay are ONNX; red points are board RKNN output.
